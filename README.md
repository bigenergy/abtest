# Блог на PHP, MySQL и Smarty

Блог с категориями и статьями на чистом PHP без фреймворков: главная с последними статьями каждой категории, страница категории с сортировкой и пагинацией, страница статьи с похожими материалами и сидер для демо-данных.

![Главная страница](docs/screenshot.png)

**Стек:** PHP 8.1+, MySQL 8, Smarty 5, SCSS, Docker (nginx + PHP-FPM + MySQL).

## Запуск в Docker

```bash
docker compose up -d --build
docker compose exec php composer install
docker compose exec php php bin/seed.php
```

Сайт откроется на http://localhost:8080.

Схема из `database/schema.sql` применяется автоматически при первом запуске MySQL. Чтобы пересоздать базу с нуля, удалите том: `docker compose down -v`.

## Запуск без Docker

Понадобятся PHP 8.1+ с расширением `pdo_mysql`, MySQL 8.0+ (запросы используют оконные функции) и Composer.

```bash
composer install
mysql -u root -p -e "CREATE DATABASE blog CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci"
mysql -u root -p blog < database/schema.sql
DB_USER=root DB_PASSWORD=secret php bin/seed.php
DB_USER=root DB_PASSWORD=secret php -S localhost:8000 -t public
```

Подключение к базе настраивается переменными окружения `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`, значения по умолчанию лежат в `config/config.php`.

## Сидинг

```bash
php bin/seed.php               # 60 статей
php bin/seed.php --articles=200
```

Сидер очищает таблицы и создаёт 7 категорий и заданное число статей (от 1 до 500):

- заголовок собирается из темы категории и шаблона, например «Индексы MySQL: шпаргалка», а слаг для адреса получается из него транслитерацией: `indeksy-mysql-shpargalka`; заголовки и слаги не повторяются;
- текст — 4–6 абзацев из набора предложений, все исходные данные лежат в `database/seed-data.php`;
- основная категория назначается по кругу, чтобы статьи распределились равномерно; примерно у трети статей есть ещё одна-две категории;
- дата публикации — случайная за последний год, просмотров от 0 до 5000, обложка — одна из SVG-картинок в `public/images/covers`;
- категория «Мобильная разработка» остаётся пустой специально: на главной её не видно, а её страница показывает заглушку.

## Тесты

```bash
docker compose exec php composer test
```

Тесты на PHPUnit 10 (последняя версия с поддержкой PHP 8.1) разделены на два набора:

- **unit** — роутер, слаги, пагинация вместе с разбором номера страницы, варианты сортировки, модификаторы Smarty, автоэкранирование, кэш шаблонов и ленивое подключение к базе. База для них не нужна: `vendor/bin/phpunit --testsuite unit`.
- **integration** — SQL-запросы репозиториев, счётчик просмотров, сидер и отдача главной из кэша, когда база недоступна, на настоящем MySQL. Они работают с отдельной базой `blog_test`, которую создаёт init-скрипт `docker/mysql/test-database.sql`, а таблицы пересоздают из `database/schema.sql` при каждом запуске. Чтобы случайно не стереть рабочие данные, тесты отказываются работать с базой, имя которой не заканчивается на `_test`. Без Docker базу `blog_test` нужно создать самостоятельно и выдать на неё права пользователю из `DB_USER`.

Init-скрипты MySQL выполняются только на пустом томе, поэтому если он создан старой версией проекта, пересоздайте его командой `docker compose down -v`.


## Как это устроено

### База данных

Основные таблицы: `categories`, `articles` и связующая `article_category`, потому что статья может входить в несколько категорий. Ещё одна, `article_views`, нужна счётчику просмотров (о нём ниже). У связующей таблицы составной первичный ключ `(article_id, category_id)` и обратный индекс `(category_id, article_id)` для выборок по категории. Внешние ключи с `ON DELETE CASCADE`, у `articles` есть индексы по `published_at` и `views` под сортировки. Слаги категорий и статей хранятся в колонках `slug` с уникальными индексами: по ним страницы и ищутся.

Все запросы идут через PDO с настоящими подготовленными выражениями (`ATTR_EMULATE_PREPARES = false`):

- **Главная.** Три последние статьи каждой категории достаются одним запросом: `ROW_NUMBER() OVER (PARTITION BY category_id ORDER BY published_at DESC)` нумерует статьи внутри категории, остаются первые три. Отдельного запроса на каждую категорию (N+1) нет. Категории без статей отсекаются через `EXISTS`.
- **Категория.** `LIMIT/OFFSET` и отдельный `COUNT(*)` по связующей таблице, без join со статьями. Варианты сортировки (по дате и по просмотрам, в обе стороны) описаны enum-ом `ArticleSort`, в `ORDER BY` он превращается через `match`, поэтому в запрос подставляется только заранее известный фрагмент SQL. Последним ключом сортировки идёт `id`: при одинаковых датах или просмотрах порядок не «плывёт» между страницами.
- **Похожие статьи.** Те, у кого больше всего общих категорий с текущей, при равенстве — более свежие. Связующая таблица соединяется сама с собой, дальше `GROUP BY` и сортировка по `COUNT(*)`. Если таких статей меньше трёх (например, статья одна в своей категории), блок добирается самыми свежими статьями — это второй запрос, и выполняется он только в этом случае.
- **Просмотры.** `UPDATE articles SET views = views + 1`: инкремент атомарный, одновременные просмотры не теряются.

### Счётчик просмотров

Чтобы ни обновление страницы, ни скрипт в цикле не накручивали счётчик, `ViewCounter` засчитывает статью один раз в сутки для каждого посетителя, то есть для пары «IP-адрес и браузер». Кто и что уже видел сегодня, хранится в таблице `article_views` с первичным ключом (статья, посетитель, день): `INSERT IGNORE` добавляет строку только при первом просмотре, и только тогда растёт `views`. Сам адрес не сохраняется, в таблицу попадает SHA-256 от адреса и User-Agent. Cookie для этого не нужны, так что работает и для клиентов без них. Роботов, которых видно по User-Agent, счётчик пропускает совсем: поисковики регулярно обходят все страницы, и это не просмотры читателей.

Для защиты нужны только сегодняшние записи. Прошлые можно удалять по расписанию или оставить как историю уникальных просмотров по дням.

### Кэш главной

Для главной нужны два запроса, и оконная функция в одном из них проходит по всем связям статей с категориями, а меняется страница только с появлением новых статей. Поэтому она кэшируется средствами Smarty: данные передаются во `View::renderCached()` коллбэком и запрашиваются только тогда, когда свежей копии нет, так что при попадании в кэш запросов нет совсем. Соединение с MySQL `Database` открывает только при первом запросе, поэтому главная из кэша к базе даже не подключается и продолжает открываться, когда MySQL недоступен. Сидер после заполнения базы сбрасывает кэш. Срок жизни ограничен пятью минутами, потому что на карточках видны счётчики просмотров и они не должны отставать дольше.

### Маршрутизация и ошибки

nginx отправляет в `public/index.php` все запросы, кроме существующих файлов. Router сопоставляет путь с шаблоном вида `/article/{slug}`, плейсхолдер принимает только корректный слаг: строчные латинские буквы и цифры через одиночный дефис. Несуществующий адрес, категория или статья, а также номер страницы за пределами диапазона отдают 404. Любое другое исключение пишется в лог, а пользователь видит страницу 500.

### Шаблоны

У Smarty включён `escape_html`, поэтому весь вывод экранируется автоматически. Страницы наследуют общий `layout.tpl` через `{extends}`, карточка статьи и пагинация вынесены в `templates/partials`. Два своих модификатора: `date_ru` выводит дату вида «8 марта 2026», `paragraphs` разбивает текст статьи на абзацы.

### Стили

SCSS собирается Dart Sass, модули подключаются через `@use`, классы названы по БЭМ, сетка карточек адаптивная: одна, две или три колонки. Собранный `public/css/app.css` лежит в репозитории, чтобы сайт работал без Node.js. Пересборка:

```bash
npm install
npm run build    # или npm run watch во время разработки
```
